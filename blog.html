Building Sati

How Sati Got Built

Rushikesh Solanke
May 2026
8 min read

The Gap

Buddhist practice involves way more than sitting quietly for 10 minutes. There is sutta study, chanting, learning about the different traditions, understanding the philosophy behind what you are doing, tracking whether you are actually staying consistent.

Most apps on the market focus on the meditation part, which makes sense since that is what the majority of users want. But for someone who is studying the Dhammapada, learning Pali chants, or working through the suttas, there was no single app that brought all of that together. Bits and pieces existed across different apps, but nothing comprehensive enough to support a full daily practice across Theravada, Mahayana, Zen, and Tibetan traditions.

That gap is what started the project.

So It Became a Project

The idea was straightforward. Take everything a practicing Buddhist would actually use on a daily basis and put it in one place. Not a meditation app with Buddhist branding. A proper practice companion.

The name is Sati. It is the Pali word for mindfulness and one of the key factors of the Eightfold Path.

Here is what ended up in it:

Meditation Timer
Bell sounds, ambient music, animated visuals, customizable duration and intervals. The basic stuff, but done properly.
Guided Meditations
30+ sessions across breathwork, metta, body scan, walking, sleep, and morning practice. I wrote a Python script using Edge TTS to batch-generate all the audio. 435+ files, male and female voices, each one paced for its category.
AI Dhamma Companion
You ask it something about your practice and it answers from the actual teachings. Not "take a deep breath and be present" type answers. Actual Dhamma. Built it on Supabase Edge Functions so the API key stays server-side and never goes to the client. Free tier gets 3 messages a day, Pro is unlimited.
Chanting Library
20+ Pali, Sanskrit, and Zen chants. The text highlights line by line in sync with the audio. I programmed the instrument layers (singing bowls, mokugyo, tingsha) with Web Audio API. This part took way longer than expected. Getting the timing right across different devices with different audio latency was a real pain.
Dhamma Learning
This is why the app exists. Structured courses on Buddhist philosophy. The full Dhammapada, all 26 chapters, all 423 verses. Sutta study with progress tracking. Content covering Theravada, Mahayana, Zen, Tibetan, and other traditions. Could not find this in any other app.
Practice Tracking
Streaks, achievements, session history, analytics. Nothing gimmicky. Just honest data on whether the practice is actually happening or not.
Retreat Mode & Sangha
Longer sessions for home retreats. Plus a community feature with shared streaks and real-time friend connections.
Five Themes
Cosmic Night, Sunrise Warmth, Pure Light, Forest Sanctuary, Ocean Depths. Built with CSS custom properties so the whole UI changes depending on which one you pick.

The Tech

Frontend
React 18, Vite, Framer Motion. Code-split and lazy-loaded.
Cross-platform
Capacitor wraps the web app into native iOS and Android. One codebase, three platforms.
Backend
Supabase for auth, PostgreSQL, Edge Functions. RLS on every table. API keys server-side only.
Audio
Python batch script with edge-tts for 435+ guided files. Web Audio API for chanting instruments.
Subscriptions
RevenueCat on iOS/Android with Supabase syncing entitlements. 7-day free trial.
Compliance
GDPR/CCPA compliant. Privacy Policy, Terms of Service, all of it.

For the audio, I wrote a Python batch script with the edge-tts library that generated all 435+ guided meditation files. The chanting instruments use Web Audio API. Getting a singing bowl to ring and decay naturally was a whole thing on its own. Took more iterations than it should have.

What Still Needs Work

Chanting Sync
Not perfect on all devices. Audio latency differences between phones cause the text highlighting to drift slightly. Works well on most devices but there are edge cases that still need fixing.
Sangha
Bare bones right now. Real-time presence works but the actual social layer needs more thought. Hard to design community stuff properly when you are the only user testing it.
AI Companion
Gets too general sometimes. If someone asks about Theravada practice specifically, the answer should stay in that tradition. Right now it occasionally drifts into a broad overview. I keep tightening the system prompt and it keeps getting better, but not fully there yet.
Not Launched Yet
Everything compiles, builds work, but a few things need to be right before launch. Soon.

Why Though

I spent too long looking for an app that treated Buddhist practice as what it actually is. Could not find one. So building it felt like the obvious next step. That is really the whole reason.
